# Actor models

The 3D view loads a mesh from the dump you point Bancwright at. Converted glTF is cached on your machine, outside this repo. The sample dump has a few synthetic meshes so the path can be tested with no Nintendo files. A real dump is still required for real actors; the checklist is [testing-on-real-dump.md](testing-on-real-dump.md).

## What gets drawn

For each actor name (`Gyaml`):

1. Open `Pack/Actor/<Gyaml>.pack.zs` (zstd dictionary 4) and read every `Component/ModelInfo/*.engine__component__ModelInfo.bgyml`. Each one, including entries under `SubModels`, has `ModelProjectName` and `FmdbName`.
2. Try `Model/<Project>.<Fmdb>.bfres.zs` (dictionary 1), then the uncompressed `.bfres`. When `FmdbName` is missing, the project name is used for both: `Model/<Project>.<Project>.bfres.zs`.
3. If that exact file is missing, try the other `Model/<Project>.*.bfres.zs` files, skipping `*.anim.bfres.zs`. When the exact file is on disk and its shapes are FSHP flag `0x10` (no decodable vertex buffer), the actor stays a box. Another fmdb in the same project is not drawn in its place. `Land_Kokiri_House_Outside_C_00` used to pick up `Land_Kokiri_House_Inside_C_03`.
4. Then `Model/<Gyaml>.<Gyaml>.bfres.zs`.
5. Older layouts still work: a `.bfres` stored inside the pack, a `Model/<name>.bfres` string in the pack, and `Model/<Gyaml>.bfres.zs`.

The first file that converts is the one shown. The same glTF is reused for every instance of that actor. Six downloads run at a time, nearest to the camera and in front of it first. Until one arrives, the actor is the labeled box, and the view stays usable. The progress chip counts models and says the rest are still loading. A static map is requested after the actors, and it is not part of picking, so a few hundred thousand triangles do not sit on the click path.

A scene draws the field from `TerrainArc`, not from the actor list. `Banc/GameBancParam/<Level>.game__banc__GameBancParam.bgyml` names `TerrainSceneName` and `TerrainScenePosition`. The mesh is `TerrainArc/<scene>.tscb` plus `<scene>_sub.tscb` when that file or folder exists. Each tile’s `<name>.hght` is read from either directory. `<name>.mate` is a block-linear 4-byte material grid and selects layers of `Tex/MaterialAlb.bntx.zs` (the same array `Mt_TerraMaterial_NNN` uses). Byte 0 and byte 1 are the two materials. 0x7f blends them halfway (a guess); an invalid index copies a neighbour instead of drawing magenta. The heightmap block at `+0x1C` is only a fallback, and a tile with neither is a flat earth colour. A coarse sample is dropped only where a finer tile emitted a quad. Height 0 is ground at the terrain origin; only a non-finite sample is a hole. The odd rows of the 257th column are read from their packed GOB slot, so a dashed column of exact zeros is not a wall down to the origin. The field is one atlas draw, with a skirt on each tile edge. It is double-sided for this test. **Tile colors** paints each tile, and a `_sub` tile is lighter. Samples are about 2 m apart near the actors and coarser farther out. `<name>.<child|adult>.bake_ao.extm` can shade the ground. `<name>.custom.extm` is not decoded. The view uses triplanar UVs with an 8 m repeat, which is still a guess. The reason says `terrain heightmap`, which is not the proxy, so **Ground** starts on and the mesh is drawn. It is not pickable, it does not cast shadows, and the actor LOD does not hide it.

If that TSCB is not in the dump, the view falls back to the first static-map bfres that exists:

- `Model/<Area>_NN.<Area>_NN.bfres.zs` (Kokiri Forest child is `Model/KokiriForest_01.KokiriForest_01.bfres.zs`)
- `Model/<Scene>.<Scene>.bfres.zs`
- the older single names `Model/<Scene>.bfres.zs`, `Model/<Area>.bfres.zs`, `Model/<Area>_Static.bfres.zs`
- the same stems under `Terrain/` and `Map/`

No map file and no TSCB means no extra object. It does not add a box. A TSCB that is present but yields no triangles does not fall back to the green stand-in.

## What is decoded

Meshes and one base color. Vertices stay in bind pose. A shape with a skin count of zero is moved by its single bone. A skinned shape is already stored in model space, so it is drawn as stored. Animation is not read.

The base color is the albedo sampler. On a version-10 material that names its samplers, that is `_a0`, then `_a1` or `_a2` if `_a0` is missing. A normal, roughness, bake, or runtime slot (`_n0`, `_rgh0`, `bake0`, `tc`, `ta`, `MaterialCmb`) is not used as the color, and the string pool is not a fallback once any sampler is named. The exception is `Mt_TerraMaterial_NNN`: it binds `ta=MaterialAlb` and `tc=MaterialCmb` with no `_a0`, and the colour is layer NNN of `Tex/MaterialAlb.bntx.zs`. That file is one ASTC 8×8 array (90 layers on the retail dump). Only the layer that material asks for is decoded, its alpha is forced opaque, the UVs repeat, and the PNG for that layer is cached. `Mt_Sand_Kokiri_Cliff` has no number. Version 10 does not store the version-9 render-info dictionary (`+0x18` and `+0x20` are the texture list, which is why those keys come back empty), so the sand cliff uses layer 16 and the log says that is a guess. A texture whose name is a normal, mask, blend, `_Fx`, `_Ind`, or `_Msk` map is not used even if it sits on `_a0`. A BC4 image is a single channel and is not a colour. If the sampler names are missing (the version-9 samples), a texture name that looks like an albedo (`_Alb`, `Albedo`, `Diffuse`) wins over `_Nrm`, and a file with no material texture can still pick one albedo-like name out of the string pool. Real textures are not inside the bfres. The viewer looks up `Tex/<TextureName>.bntx.zs` (dictionary 1), then the same stem with or without an `_Alb` suffix, then an image of that name inside a `.bntx` that holds several images. It does not substitute a different image from that file. Lookup is case-insensitive. An embedded BNTX is still used when the bfres has one.

`Model/KokiriForest_01.KokiriForest_01.bfres.zs` in the retail dump is a dummy: one material, no textures, positions only. It is used only when the scene has no TerrainArc TSCB. The converter writes that mesh as a flat-shaded earth-green material and the reason says `terrain proxy`. The view does not draw it. **Ground** is off for a proxy, and turning it on shows a neutral grid at the mesh’s median height, not the green triangles. A static map that does name an albedo, and a decoded heightmap, are shown with Ground on. The proxy is not looked up in `Tex/`. Path strips and moss mounds that already draw are actor models (`Land_*`, field props). They are not a substitute for the heightmap. Shapes omitted as InnerMesh, bake, fade, or water volume stay omitted; those names are not the field. FSHP flag `0x10` is still not decoded. `scripts/check_terrain.py` lists, for one scene, which heightmap tiles were drawn or skipped and which ground-like actors are still flag `0x10`.

Tile mode and block compression (BC1–BC7, ASTC, RGBA8) are decoded on the server to JPEG or PNG and packed into a glTF binary. An unlisted channel type on a known block family (the same codec as `0x1A01` with a different low byte, for example) uses that codec and the texture log names the id. The block height is the low 3 bits of BRTI+0x34. If that value’s padded surface does not match the mip-table size, the size picks the height. When several heights share that size and the stored one decodes as strong moiré, a much smoother height replaces it and the log says `swizzle log2 N, stored M looked like noise`. A texture that stays noisy keeps the stored height and says so. ASTC ids `0x37`–`0x3A` are 10×8, 10×10, 12×10, and 12×12. A BC1 block with color0 ≤ color1 treats index 3 as transparent, which is the sky on the FarView cards. An all-zero ASTC block on a last GOB row that is not a multiple of 8 is replaced with the block above. A failed decode, an unsupported format, or a solid magenta image is not bound: that part is a flat colour (the material’s colour parameter, or a neutral grey) and it does not reuse another part’s texture. Magenta texels in an otherwise real image are punched out and the part is drawn as cutout.

A material whose name or texture is water, a lake, a river, or the sea (not an NPC) is drawn unlit and translucent, with depth write off, after the opaque meshes. The colour is a desaturated teal at about 20% alpha (`0.35, 0.55, 0.55, 0.2`), whether or not an albedo was usable. `custom` on that material is blend. If it has no usable albedo, or the bound image is a normal map, a flat pale sheet, or still noisy after the swizzle retry, the mesh is that same stand-in (`water stand-in` in the reason and in `scripts/check_models.py`) instead of the neutral cream colour. When a model has both `Mt_Water_Back_Flowmap` and `Mt_Water_Front_Flowmap`, only the front sheet is drawn, so the two coplanar layers do not stack into an opaque floor. **Water** in the viewport hides those sheets; it starts on. Shapes named as a water volume, a bake shadow proxy, fade-black, or an inner mesh are not drawn. `Mt_Eye_Outer` and `Mt_Eyeshadow` are not drawn. An eyebrow does not reuse the face texture. Other blend materials also skip the depth write, so a translucent sheet does not stack into a green slab under the green fill light.

Version-10 alpha comes from the render-state string array. The u16 at FMAT `+0xA0` is 0 or 1 and is not that array’s length; the reader walks the 31 slots at the `+0x40` pointer and stops on a null or a non-string. Index 11 `mask` (or index 15 `true`) is glTF `MASK`, `translucent` is `BLEND`, and index 10 `both` is double-sided while `front` is single-sided. `custom` stays opaque except on a water material. Version-9 files still use the named `gsys_*` render info. The view turns on alpha-to-coverage for a mask. An opaque shape that shares its positions with a masked twin (FarView and FarView_Shaking) is dropped, so the opaque copy does not paint the punched sky black. `scripts/check_models.py` prints one block per material and says `textured` or `flat` for that material, then the shape names. A flat material also prints `flat fallback`. The summary counts shapes that received an image and shapes that used the flat colour. It does not call an actor textured because one of its materials was. The block still lists the sampler names, the texture each one references, which one was used as the albedo, the `Tex/` path, whether it decoded (format, size, swizzle, block height), the alpha mode, and the render-state word. A missing `Tex/` file borrows the nearest sibling albedo when one letter of the name differs and that file exists (`Rock_Kokiri_FieldProp_J_Alb` uses `FieldProp_I` or `FieldProp_K`). If there is no sibling, the flat colour follows the name: rock is grey-brown, vine or leaf is green, cloth or wood is tan, instead of the neutral cream. The log says which file was borrowed or which colour was used. A bake-only material stays flat. A water material with no usable albedo is the faint teal stand-in, not the cream flat colour. A mask whose alpha channel is empty keeps the cutout by using the colour as the alpha, so a beard card does not become a solid plane.

## Build-time actors

An After the Ocarina recipe that places an actor (the `stones:` list, or any other scene YAML row with a gyaml, a translate, and a banc) is drawn on that map before you build. It keeps the violet tint and the label “added by build, flag-gated” when the file names a flag. It is editable: the gizmo and the properties panel write `translate`, `rotate`, `scale`, and `params` back into that YAML (comments kept), and the build uses those values. Y in the file is the gizmo Y minus `y_offset`, so the offset is not applied twice. Hide and Delete ask, then remove the list entry. Duplicate adds a copy one metre along X. Undo, the Changes tab, and Revert use a snapshot taken the first time that file is edited (`.bancwright/recipe-baseline.json`). Saria’s file leaves `place: false` and does not add a ghost.

Areas, fog, triggers, sensors, collision, and anything else that is not a real mesh and is 8 metres or larger on an axis are edge outlines in a neutral colour. The fill is drawn only for the volume that is selected, so a stack of areas cannot tint the forest. The fill does not write depth. The outliner has a Volumes chip that hides every outline at once, plus a chip per category. The stage-bar Show / Lock / Hide for Areas and System is unchanged.

The cache key is a hash of the source bytes plus a version prefix (`models-16`). Older glTF in that folder is left unused. A heightmap remembers both TSCBs, each `.hght`, `.mate`, and bake-ao file it read, the terrain folder mtimes, and `Tex/MaterialAlb.bntx.zs`. A second file, `src/<hash>.json`, remembers which texture files that glb was built from. The next open stats those files and returns the glb without parsing the bfres or decoding textures. Each unique BNTX is decoded once into `bntx/`, and the JPEG or PNG is reused from `img/` when another model shares those pixels. The view still batches meshes that share an albedo. Files live in `$BANCWRIGHT_CACHE`, or `$XDG_CACHE_HOME/bancwright/models`, or `~/.cache/bancwright/models`. Cold converts run in four worker processes (`BANCWRIGHT_WORKERS`, `0` or `1` keeps them in the server process). Those workers ignore Ctrl+C, and the pool shuts down without waiting when the server stops, so a terminal interrupt does not print a KeyboardInterrupt from each worker. A warm open should be well under half a minute. The first open is the one that converts, nearest models first, and the scene can be used while the rest arrive.

## Drawing

Every placeholder is an outline. A missing model, an FSHP flag `0x10` shape, a recipe that has not loaded, and a companion that has not loaded use an edge line plus a very faint fill, both with depth write off. A volume uses the outline only, and the faint fill appears while it is selected. A real mesh hides that box. Nothing in the placeholder path uses a solid material.

Static meshes that share an albedo (same image, alpha mode, and colour) go into one `BatchedMesh`. One multi-draw covers every copy and every other model on that material. The batch id maps back to the actor for picking. Moving, selecting, or hiding an actor updates that instance’s matrix, colour, or visibility. Each instance is frustum-culled. The camera far plane starts at 8000 m and frames to at least 4000 m, or 80 times the scene radius. A prop under about 1.2 m is dropped past 56 m, under 3 m past 96 m, and under 8 m past 180 m. Anything that still covers fewer than about three pixels is dropped until you get closer. **Stats** in the stage bar shows fps, the draw count, how many draws the same actors would cost without batching, and the triangle count. Shadows are off, and the pixel ratio is capped at 1.5.

A BFRES shape’s LOD list is an array of 0x38-byte mesh headers (`FSHP+0x5B` is the count). The glTF keeps LOD 0 and, when a later level has fewer triangles, that coarser level under a `lod1:` node. The view draws one of them: LOD 0 inside 44 m, the coarse mesh past that. The selected actor stays on LOD 0. Shapes with no second level and more than about 300 triangles get a grid-quantized far mesh in the same cache; larger meshes use a coarser grid. Submeshes of a single level are one mesh, not stacked LODs.

Fly mode hides the cursor on right-button down (pointer lock) and turns with the mouse movement, including once the cursor would have left the view. Releasing the button, or Esc, gives the cursor back. WASD still moves while the button is held. The view renders when the camera moves, the selection or a transform changes, or a model arrives. Orbit damping finishes the frame it needs and then the loop stops. Labels are the selection, the actor under the cursor, and the nearest 24 when **All labels** is on. Picking uses a BVH (`three-mesh-bvh`) on the source mesh for the batch id the ray hit. A textured static map is merged per material and is not pickable. The untextured Kokiri stand-in is not in the scene unless Ground is on, and then it is the grid. Companion actors share the same batches; their color is dimmed, and **Pick companions** only changes whether the ray keeps the hit. Moving one still writes that actor’s own banc.

Albedo images are capped at 1024 on the long edge. An opaque image is stored as JPEG, a cutout stays PNG, and the GPU builds mipmaps. The API gzips glTF and JSON responses over 1 KB. Model fetches run six at a time, nearest and in front of the camera first, and a converted glTF is reused from the cache without decoding it again. `EXT_meshopt_compression` is not applied: the encoder is a separate toolchain, and the draw-call and LOD cuts are the part that moves frame time.

A native shell (Tauri or Electron around this same three.js view, or a native engine) would not change the Kokiri cost. The time goes to draw submissions and to full-detail meshes in the distance, which is the same work on either side of a webview. The editor stays a browser page.

## Companion bancs

Opening a scene also loads its sibling: `_Static` with `_Dynamic`, same folder and the same age. The scene name in the bar gains “with Dynamic” or “with Static”. Those actors are drawn slightly dimmed, on by default. **Companion banc** hides them. **Pick companions** (on by default) lets you select them; off, they stay visible and clicks pass through. Selecting one switches the banc that Move, Rotate, and the properties panel write. The file you opened stays the host. Undo puts both diffs back.

Kokiri Forest child is the case this is for. The houses are in `KokiriForest_Child_Dynamic` (42 of 43). The NPCs are in Static, with their feet near y = 117, which is the floor of those houses. Static alone looks like the characters are floating.

`GET /api/models/<Gyaml>` returns `status` (`mesh` or `box`), `reason`, `source`, `triangles`, and `textures`. `GET /api/models/<Gyaml>/model.glb` is the file. Terrain uses `/api/terrain?banc=` and `/api/terrain/model.glb`.

## What stays a box

The properties panel shows the reason.

- No pack, and no `Model/<Project>.<Fmdb>.bfres.zs` or `Model/<Gyaml>.<Gyaml>.bfres.zs`. The properties panel lists the paths it tried.
- The pack is not a SARC, or the bfres is truncated or not a Switch `FRES` file.
- `.bfres.mc` (mesh codec). This viewer does not decode that stream.
- FSHP flag `0x10` (flags word `0x12`). The vertex buffer is not an FVTX and the mesh count is 0. The box uses the shape’s center and extent. The reason is `geometry format not decoded (FSHP flag 0x10)`. The layout after the GPU buffer is not documented as a meshlet or `.bfres.mc` block, so it is not decoded.
- The GPU buffer is an external section past the end of the file (the HasExternalGPU flag).
- A vertex format this reader does not know.
- The glTF request failed in the browser. The outline comes back and the reason is the load error. The warning strip shows that error.

## Picking

Areas, system actors (`StartPos`, `Player`, `Sound`, `AirWall`, `Ground`, names with `Anchor`, names ending in `Actor`), names containing `Trigger`, and land actors scaled to 8 metres or more on any axis are volumes. They are drawn as an edge outline. A fill is added only while that volume is selected. A ray prefers the closest solid (a real mesh, or an ordinary box). A volume is selected when the click is on its edge, or when the ray hits nothing else. Alt-click, or another click on the same stack, cycles. **Areas** and **System** can be shown, locked (visible, not pickable), or hidden. A real mesh on a volume actor is picked like any other mesh.

## Sources

The reader in `bancwright/formats/bfres.py` and `bntx.py` is original. Field order and the Switch vertex-format ids follow [KillzXGaming/BfresLibrary](https://github.com/KillzXGaming/BfresLibrary) (MIT), checked against the public Wexos BFRES and BNTX notes. Block compression uses [texture2ddecoder](https://pypi.org/project/texture2ddecoder/) (MIT). The Tegra block-linear swizzle in `bancwright/formats/swizzle.py` is an original implementation of the GOB layout in the Tegra X1 TRM. Switch Toolbox and AboodXD’s BNTX tools were not copied; their swizzle code is GPL.
